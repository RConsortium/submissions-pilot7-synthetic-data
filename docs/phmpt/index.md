# PHMPT reproduction with yamaa

FDA released the submitted SDTM, ADaM and Define-XML of 4 COVID-19 vaccine trials on [phmpt.org](https://phmpt.org/). AI agents wrote a [yamaa](https://elong0527.github.io/yamaa/) specification for each submitted ADaM dataset, yamaa ran it on the submitted SDTM, and scripts compared the result with what the sponsor submitted. This page tells what was done and what was found; each chart links to the evidence behind it. Every result is a draft pending human review.

## What was attempted

Of the 22 studies FDA released on PHMPT, 4 include ADaM datasets: 166 datasets in 15 deliverables, each given a yamaa spec. Before any comparison, an [analysis set](glossary.md#analysis-set) fixes what the release can support: the datasets, columns and cells whose every input was released. Within it, **154 of 158 datasets, 15,978 of 16,119 columns and 5,472.13M of 5,472.17M cells are fully reproduced**.

## How it was done

Each dataset went through the same five steps. AI agents drafted, yamaa executed, scripts compared, and people decided how each difference is reported ([responsibilities](#responsibilities)).

<div class="phmpt-steps" role="list" aria-label="How each dataset was reproduced">
<div class="phmpt-step" role="listitem"><span class="phmpt-role phmpt-role-auto">Script</span><strong>1. Fetch</strong><span>Read the released SDTM, ADaM datasets and Define-XML from the PHMPT zips, only the members needed.</span></div>
<div class="phmpt-step" role="listitem"><span class="phmpt-role phmpt-role-ai">AI drafting</span><strong>2. Specify</strong><span>Write a yamaa spec for each ADaM dataset, porting the sponsor&#x27;s SAS where it was released (186 program files in 3 of the 4 studies).</span></div>
<div class="phmpt-step" role="listitem"><span class="phmpt-role phmpt-role-engine">Engine execution</span><strong>3. Execute</strong><span>yamaa runs each spec on the submitted SDTM and composes the define from the same specs.</span></div>
<div class="phmpt-step" role="listitem"><span class="phmpt-role phmpt-role-auto">Automated check</span><strong>4. Compare</strong><span>Cell by cell with the submitted dataset; element by element with the received define.</span></div>
<div class="phmpt-step" role="listitem"><span class="phmpt-role phmpt-role-human">Human review</span><strong>5. Decide and review</strong><span>Each difference gets a recorded reason and a dated owner decision; reviewers assess single findings.</span></div>
</div>

## Define-XML

## What this shows and what it does not

- **Agreement is not validation.** A verdict compares yamaa's output with the dataset the sponsor submitted. Agreement shows that the specification reproduces the submitted values from the released inputs. It is not regulatory validation, and it does not show that a derivation follows the analysis plan.
- **Not every match is exact.** *Matches except missing input*, *reproduced on a substitute input* and *matches except a defect of the submitted file* are reported apart from exact, with the absent input or the defect named and every differing cell counted.
- **Carried columns are not derived.** In mRNA-1273-P201 Addendum 1 (BLA 125752 S3), 5 ADIS columns and 26 ADSL columns are copied from the submitted datasets, because the input they are derived from is not in the release. Some specs also read another submitted ADaM dataset as input where the program does; the dataset's notes name it.
- **The define text was transcribed, not authored.** The labels, methods, comments and origins in the composed defines come from the received defines through the reproduced-mode layer. Define agreement shows that yamaa can express and write every element of those documents, apart from the named defects of the submitted define, which yamaa does not copy; it does not show that yamaa authored that text.
- **Some inputs are not in an open format.** 40 input files are on PHMPT only as JMP tables. The published results used reviewed conversions kept in the frozen development repository; to rerun a dataset that reads one, you supply your own conversion (steps in [`phmpt/reproduce.sh`](https://github.com/RConsortium/submissions-pilot7-synthetic-data/blob/main/phmpt/reproduce.sh)).
- **A successful run is not a review.** Every result is a draft until a person reviews it.

## Responsibilities

| Role | Responsibility |

| Human review | The project owner sets the scope and the comparison rules, decides how each kind of difference is reported ([owner decisions](https://github.com/RConsortium/submissions-pilot7-synthetic-data/blob/main/phmpt/DECISIONS.md)), and reviews and merges every change in Pilot 7 through a pull request. Reviewers check single findings and record their assessment on the [review page](review/index.md). |
| AI drafting | AI agents (Claude) drafted the specifications, the fetch, verify and define scripts, the recorded reason for each difference and these pages: until 2026-11-27 in a private development repository, now frozen, and since then in Pilot 7. Their output is a draft until a person reviews it. |
| Engine execution | yamaa, at the commit pinned in `yamaa.lock` (`ac826f0`), executes each specification on the submitted SDTM and composes each define from the specifications and the reproduced-mode layer. |
| Automated checks | Scripts compare every output with the submitted dataset or the received define and record the result; the publication gate checks every PHMPT file in Pilot 7; CI reruns part of the reproduction from PHMPT on each change. |
