# Pilot 3 ADaM derivations

Five single-output yamaa specifications derive the official Pilot 3 ADaM
datasets from SDTM. Run `python/run.py` from this directory to execute the
specs in dependency order and write `../../data/adam/<dataset>-yamaa.parquet`.
Every ADaM variable is derived in a specification. `python/compare.py` checks
all official columns and cells at an absolute numeric tolerance of 1e-10,
and compares the YAML label declarations with the official labels.

```bash
cd submission-pilot3/program/adam
pip install -r python/requirements.txt
python3 python/run.py
python3 python/compare.py
```

The dependency order is ADSL, ADAE, ADADAS, ADTTE, ADLBC. All downstream
specs read the derived ADSL; ADTTE also reads derived ADAE. The current
yamaa revision (`44aa32c`) supports `to_date` on the collected ISO `QSDTC`
text directly in `adadas.yaml`, so the runner no longer constructs a
`QSDTC_D` source column.

ADAE and ADLBC read the derived ADSL through an implicit join on `STUDYID`
and `USUBJID`; neither needs a named intermediate for that key match. In ADADAS,
the two row templates supply source-specific values, while `TRTSDT`,
`ADY_RAW`, and `AVISIT` are derived once at column level.
The pinned revision indexes implicit joins once per run (yamaa issue #1485).

The ADADAS planning relation is generated by `python/make_plan.py` from
SDTM QS/EX and a compact visit schedule. `inputs/plan.csv` is the pinned,
reviewed result, checked for drift in CI. The 4-row
`inputs/aw_lookup.csv` defines analysis windows. ADADAS reads both CSVs
directly with declared numeric types.

Every output column declares a label in its specification, and the comparison
checks it against the official Parquet field metadata.
