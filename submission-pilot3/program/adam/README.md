# Pilot 3 ADaM derivations

Five single-output yamaa specifications derive the official Pilot 3 ADaM
datasets from SDTM. `python/run.py` stages the input parquets and two planning
relations, runs the specs in dependency order, and writes
`work/adam/<dataset>-yamaa.parquet`. Every ADaM variable is derived in a
specification; the runner adds Parquet label metadata from each spec's
`label:` declarations. `python/compare.py` checks all official columns, labels,
and cells at an absolute numeric tolerance of 1e-10.

```bash
cd submission-pilot3/program/adam
pip install -r python/requirements.txt
python3 python/run.py
python3 python/compare.py
```

The dependency order is ADSL, ADAE, ADADAS, ADTTE, ADLBC. All downstream
specs read the derived ADSL; ADTTE also reads derived ADAE. The current
yamaa revision (`6ab77309`) supports `to_date` on the collected ISO `QSDTC`
text directly in `adadas.yaml`, so the runner no longer constructs a
`QSDTC_D` source column.

ADAE reads the derived ADSL through an implicit join on `STUDYID` and
`USUBJID`; it needs no named intermediate for that key match. In ADADAS,
the two row templates supply source-specific values, while `TRTSDT`,
`ADY_RAW`, and `AVISIT` are derived once at column level.

ADLBC keeps its keyed `ADSL1` intermediate for performance: the pinned
yamaa revision scans ADSL for each implicit read (yamaa issue #1485),
which was fixed in a later revision.

The ADADAS planning relation is generated by `python/make_plan.py` from
SDTM QS/EX and a compact visit schedule. `inputs/plan.csv` is the pinned,
reviewed result, checked for drift in CI. The 4-row
`inputs/aw_lookup.csv` defines analysis windows. The runner converts both
CSV inputs to Parquet with declared types; they are inputs, not ADaM
outputs.
